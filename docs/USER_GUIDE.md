# THEIA 用户手册

这份手册面向第一次使用 THEIA、也可能不熟悉命令行的用户。建议第一次从头阅读第 1 至第 8 章；遇到错误时再查第 14 章和单独的 [故障排查手册](TROUBLESHOOTING.md)。

## 1. 先理解 THEIA 是什么

THEIA 的工作方式不是“自动偷看聊天”，而是：

1. 你用已有导出工具把聊天保存成 JSON、CSV 或 TXT。
2. 你在 THEIA 中选择文件或授权一个目录。
3. THEIA 在本机解析、整理、去重，并让你查看原始会话。
4. 你选择要处理的会话和时间范围，点击模型提炼。
5. 选中的文本经本机代理发送到你配置的模型服务。
6. 模型结果先成为“候选”，由你确认后才进入任务图。
7. 私聊中的人物信息会在任务提炼之后继续处理，并显示独立进度。

不配置模型服务时，仍可导入和浏览记录、手动创建任务、编辑行程及地图标记。自动候选、人物画像和个性化建议需要模型服务。

## 2. 安装前准备

### 2.1 支持的系统

发布包的两个 `.cmd` 启动器面向 Windows 10/11 x64。建议使用仍在微软支持期内的系统，并安装最新显卡驱动。

### 2.2 安装 Node.js

THEIA 当前至少需要 Node.js `22.12.0`，推荐安装 Node.js 24 LTS x64。Node.js 20 不满足当前 Electron 和 OpenAI SDK 的要求。

安装步骤：

1. 从 Node.js 官方网站下载 Windows x64 LTS 安装包。
2. 使用默认选项安装，确保勾选加入 PATH。
3. 安装后重新打开 PowerShell。
4. 输入以下命令：

```powershell
node --version
npm --version
```

`node --version` 应显示 `v22.12.0` 或更高。项目当前使用 `v24.13.0` 验证。

### 2.3 硬件与空间

- 安装依赖建议预留至少 1 GB。
- 数万条聊天在 8 GB 内存机器上通常可用；数十万条建议 16 GB 或更多。
- 桌面版默认使用 GPU 渲染任务图、地图和大背景。集成显卡也可以，不要求独立显卡。
- 原始聊天、日志和头像会持续占用空间。模型工作日志记录得很详细，长期使用需要定期归档。

### 2.4 网络依赖

| 功能 | 是否需要网络 |
| --- | --- |
| 打开任务图、查看已保存任务 | 否 |
| 导入和查看本地聊天 | 否 |
| 安装 npm 依赖 | 首次需要 |
| 模型列表与模型提炼 | 需要 |
| 地图底图与地点搜索 | 需要 |
| 未来天气建议 | 需要 |
| 在线语录 | 需要；失败后用离线句库 |
| 下载聊天导出中的远程头像 | 需要；失败后显示文字头像 |

## 3. 安装发布包

发布包是“源码发布版”，不是免安装软件。目录大致如下：

```text
THEIA-release/
  app/
  assets/
  data/
  docs/
  logs/
  启动 THEIA 桌面版.cmd
  启动 THEIA 浏览器版.cmd
```

第一次安装依赖：

1. 打开 `THEIA-release` 文件夹。
2. 进入 `app` 文件夹。
3. 在文件夹空白处按住 Shift 并点击鼠标右键，选择“在终端中打开”；也可以在资源管理器地址栏输入 `powershell` 后回车。
4. 运行：

```powershell
npm install
```

看到命令返回提示符且没有红色错误后，安装完成。`app/node_modules/` 会占用较多空间，这是正常现象。

如果网络很慢，不要反复删除 `node_modules`。先确认 npm 官方源可访问；必要时在可信网络下重试，npm 会复用已下载缓存。

## 4. 启动和关闭

### 4.1 推荐：桌面版

双击发布包根目录的 `启动 THEIA 桌面版.cmd`。它会：

- 检查 Electron 依赖是否已安装；
- 结束此发布目录记录的旧 THEIA 桌面进程；
- 启动本地 API、Vite 页面服务和 16:9 Electron 窗口；
- 默认开启 GPU 光栅化、零拷贝和画布离屏光栅化。

关闭时直接关闭 THEIA 窗口。状态写入有短暂防抖，重要修改后建议等一秒再退出。

### 4.2 浏览器版

双击 `启动 THEIA 浏览器版.cmd`，终端会显示本地地址，通常为：

```text
http://127.0.0.1:5173/
```

用最新版 Chrome 或 Edge 打开。运行期间不要关闭命令行窗口。浏览器目录连接依赖 File System Access API，Firefox 和部分内置浏览器可能无法使用“连接目录”。

### 4.3 桌面版和浏览器版是否同步

同一个发布目录启动的桌面版与浏览器版通过 `data/state.json`、`data/chat-archive.json` 和 `data/settings.ini` 共享主要数据。同步不是云同步，也不会跨电脑自动传输。

不要同时打开多个指向同一发布目录的副本并高速编辑同一批数据。应用会比较快照时间并串行写入，但它不是多人协作数据库。

### 4.4 显卡异常时的软件渲染

若窗口全黑、花屏或驱动崩溃，在发布包根目录打开传统命令提示符，运行：

```cmd
set THEIA_SOFTWARE_RENDERING=1
启动 THEIA 桌面版.cmd
```

软件渲染会明显变慢，只用于诊断或显卡驱动确实不可用的情况。恢复正常启动后会重新使用 GPU。

## 5. 第一次配置

### 5.1 名称、头像和背景

打开左侧“选项”，在“界面外观”中点击“编辑外观”：

- 名称用于侧边栏和任务图中心，不影响模型判断发言方向。
- 用户头像可以上传本地图片，也会显示在任务图中心。
- 可选择苍翠、夜色、纸页、樱色等主题。
- 全局背景支持本地上传或 HTTP(S) 图片地址。
- 缩放改变背景尺寸，模糊度只影响背景，不应遮住主要文字。
- “启用动态背景与轻微视差”控制轻微运动；低性能设备建议关闭。

上传图片最大 20 MB，支持 PNG、JPG、WebP、GIF 和 AVIF。发布布局下图片写入 `assets/img/backgrounds/`。

### 5.2 配置模型通道池

仍在“选项”中，找到“模型通道池”。第一条配置默认叫“主通道”：

1. 填写服务地址，例如服务商给出的 API 根地址。
2. 填写 API Key。界面按当前产品要求明文显示，方便检查。
3. 点击检测模型列表。
4. 从返回列表中选择支持对话和结构化 JSON 输出的模型。
5. API 模式通常选“自动”。
6. 设置这条通道允许同时运行的请求数，第一次建议从 1 或 2 开始。
7. 保存并观察该行是否显示“可用”。

如果单条 API 的带宽、并发或频率额度不足，点击“添加通道”，为另一条独立服务地址或 API Key 重复上述步骤。THEIA 会把不同会话按当前负载分配给可用通道；同一会话的连续片段仍按时间顺序处理，不会并发打乱上下文。列表中的星标用于选择主通道，启停按钮可临时排除某条通道，删除按钮只移除本机配置。

通道池有两层并发限制：

- “通道并发容量”限制单条 API 同时承担多少请求，范围 1–8；
- “并发会话”限制整轮提炼同时处理多少个不同会话，范围 1–32；
- 实际上限取两者中较小的可用容量。可点击“将全局并发设为……”使用当前通道池总容量。

两条 Key 如果属于同一个账户、同一中转或同一上游，仍可能共享总限额，不一定线性提速。优先使用服务商明确允许的独立通道，并遵守其额度与使用政策；不要用通道池规避访问控制或安全策略。

地址规则：

- 服务地址没有路径时，THEIA 自动补 `/v1`。
- 远程地址必须是 HTTPS；只有 `localhost` 和 `127.0.0.1` 允许 HTTP。
- 地址应是 API 根地址，不是服务商网站首页、控制台或聊天页面。
- 模型探测请求为 `GET <base-url>/models`，使用 `Authorization: Bearer <key>`。
- 自动模式优先尝试 Responses API；通道明确不支持时回退到 Chat Completions。

所有通道、主通道选择、模型和并发容量都保存在 `data/settings.ini`，其中包含明文 API Key。不要把它发给别人，也不要提交到代码仓库。

### 5.3 导入连接 JSON

如果服务商提供以下格式，可在选项中导入。每次导入都会新增一条通道，不会覆盖已有通道：

```json
{
  "_type": "newapi_channel_conn",
  "url": "https://api.example.com",
  "key": "sk-example-replace-me",
  "model": "example-chat-model",
  "apiMode": "auto"
}
```

示例中的 Key 是假的。真实 Key 不应写进截图、README 或问题报告。

### 5.4 模型提示词

THEIA 有四组可编辑补充指令：

| 指令 | 作用 |
| --- | --- |
| 任务提炼 | 决定什么现实事项值得成为候选、摘要应怎样表达 |
| 人物证据 | 决定如何从私聊中提取事实、偏好信号和引用 |
| 人物归并 | 当事实缓冲过长时，如何保守收敛人物刻画 |
| 任务建议 | 如何结合人物、时间、地点和天气给行动建议 |

自定义提示词是补充规则，不能覆盖程序的硬约束：引用必须存在、任务执行者必须是你、旧消息不能自动变成新任务、未知时间不能估算、发言方向不能靠想象翻转。

建议每次只改一项，用 1 至 3 个会话测试，并保留有效措辞。过长、互相矛盾的提示词通常会降低稳定性。

## 6. 准备聊天导出

最推荐的目录结构是一个文件夹代表一个会话，并明确区分私聊和群聊：

```text
聊天导出/
  私聊/
    林晓/
      messages.json
    周然/
      messages.json
  群聊/
    班级通知群/
      messages.json
```

THEIA 会把“私聊/单聊/好友/direct/personal”识别为私聊，把“群聊/群组/群消息/group/chatroom”识别为群聊。分类文件夹下一层作为会话身份。

导出记录至少应包含：

- 消息正文；
- 消息时间；
- 发言人名称；
- 能可靠表示消息是你发送还是对方发送的字段；
- 可选的消息类型；
- 可选的头像 URL，可能位于消息、发言人对象或顶层 `session.avatar`。

只写昵称而没有 `isSelf`、direction、发送者 ID 与本人 ID 对照时，THEIA 不会猜谁是你。详见 [聊天导出格式](CHAT_EXPORT_FORMAT.md)。

## 7. 导入文件与连接目录

### 7.1 单次导入

在“情报库”的“情报接入”区域选择 JSON、CSV 或 TXT 文件。一次选择适合测试或临时导入。

### 7.2 连接目录

“连接导出目录”会请求浏览器对指定文件夹的只读权限。THEIA 递归扫描：

- 最多 20,000 个支持的文件；
- 最大目录深度 24 层；
- 单文件最大 50 MB；
- 只读取 `.json`、`.csv`、`.txt`；
- 按路径、大小、修改时间和导入器版本生成签名；
- 再次扫描时只处理新文件或发生变化的文件。

当前不做后台文件系统监听。每次页面启动会尝试恢复已授权目录句柄并执行一次扫描；Windows 或浏览器可能要求重新确认权限。你也可以随时点击手动扫描。

### 7.3 导入后必须检查

不要导入后立刻处理全部历史。先打开一个熟悉的私聊会话，检查：

1. 消息数是否与导出大致一致。
2. 最新聊天时间是否正确。
3. 消息顺序是否从旧到新。
4. “你”和“对方”是否正确。
5. 发言人名称是否在群聊中保留。
6. 图片消息是否至少保留了可识别文字、路径或类型。
7. 会话头像是否能从 `session.avatar` 或消息字段读取。

如果方向错误，先修导出映射或 JSON 字段；不要试图用模型提示词补救。

## 8. 选择分析范围

情报库支持两种容易混淆但用途不同的时间模式。

### 8.1 最后聊天时间

它先看每个会话的最后一条消息是否落在你选择的时间段；符合条件后，提交该会话中已导入的完整历史。

适合：

- 最近仍在联系的人；
- 需要历史上下文理解关系、长期约定和人物偏好；
- 希望完整更新人物卡。

注意：一个最近刚聊过的老朋友可能有数万条历史消息，这种模式会覆盖全部历史，模型请求数较多。

### 8.2 严格时间

它先选会话，再把开始时间之前和结束时间之后的消息完全裁掉，只提交指定范围内的记录。

适合：

- 只找最近一周或一个月的新任务；
- 排查超长上下文和 502；
- 避免早已过期的历史通知干扰任务候选。

严格时间会减少人物历史上下文。如果目标是人物刻画，可单独用最后聊天时间模式处理相关私聊。

### 8.3 单一会话

排错和磨合时优先选择一个会话。先让一个你熟悉的聊天得到合理候选，再批量运行。这样能区分“导入字段错误”“提示词错误”和“模型服务不稳定”。

## 9. 模型提炼如何运行

### 9.1 超长会话不是随机抽样

THEIA 会覆盖所选范围内的全部消息，但第三方模型和 Cloudflare 通常不能接受无限长的单个 HTTP 请求。因此超长会话会按字符预算连续分段：

- 每段核心预算约 14,000 至 34,000 字符，长会话会使用更小的段；
- 下一段最多带上前一段的 24 条、4,000 字符作为上下文重叠；
- 每条消息只在一个“核心段”产生任务，重叠消息只帮助理解上下文；
- 61 天以前的历史段仍可用于长期事实，但只能输出明确仍有效或未来发生的任务；
- 最近段优先运行，历史段随后运行。

这意味着“全量覆盖”不等于“一个巨大请求”。连续分段是为了避免 502、上下文上限和超时，同时不丢掉消息。

### 9.2 发送给模型的核心字段

每条记录压缩为稳定数组，字段顺序为：

```text
[RecordRef, formattedTime, type, content, senderDisplayName, speakerRole]
```

`RecordRef` 是本段中的短引用号；模型返回后，服务端会恢复为原始消息 ID。附件最多 4 个，每个不超过 8 MB，并且只随会话的第一段发送。

### 9.3 重试与停止

对临时服务错误，单个请求最多尝试 5 次，使用短退避和服务端 `retry_after` 提示。连续服务失败时，未处理工作保留，界面会显示重试入口。

启用多条通道后，调度器优先选择当前负载最低且未冷却的通道。某条通道出现 429、502、503、504、524、网络错误或超时，会单独进入短暂冷却；其他健康通道继续接收会话。前端重试同一片段时会重新排队，因此可以落到另一条通道。通道池不会把同一个失败请求同时复制给所有服务商，避免重复计费。

点击停止后：

- 不再启动新的任务提炼请求；
- 已完成的候选保留；
- 已生成的人物卡保留；
- 当前网络请求会尽快中止；
- 可以缩小范围或服务恢复后重试。

### 9.4 私聊任务与人物联合处理

私聊会话会在同一次分段请求中同时提炼任务和人物证据；群聊仍只提炼任务。这样不需要把同一份私聊再次完整上传，通常能显著减少输入 token 和等待时间。只有兼容服务没有返回联合人物结果，或某个私聊片段失败时，THEIA 才会对未覆盖会话使用旧人物接口回退，并在工作浮窗显示人物处理进度。

人物结论必须引用原消息 ID。单次“蛋挞好吃”只能形成较弱偏好信号，不应直接写成稳定性格。人物事实累积过多时，THEIA 会把已核验事实交给归并提示词做保守收敛，最多自动重试 3 次。

## 10. 审核候选任务

模型结果不会直接成为正式任务。候选列表中应重点检查：

- 这件事是否仍需要你行动；
- “谁请谁”“谁答应谁”是否正确；
- 目标时间是否来自原文，而不是信息源时间；
- 没有明确目标时间时，是否只显示信息源时间；
- 已过期的快递、旧投稿、旧报名是否被排除；
- 是否能打开并找到引用的原始消息；
- 标题是否是清晰行动，而不是聊天摘要。

可以勾选多个候选后生成，也可以一键生成全部当前候选。忽略候选时选择“已过期、执行者错误、已完成、不可行动、内容错误”等原因；这些“磨合记录”会加入后续任务提示。磨合记录可以在选项中打开浮窗、逐条删除或折叠隐藏。

生成任务后，THEIA 会尝试：

- 关联已有的人物卡；
- 根据明确地点搜索坐标并创建地图点；
- 对行政区、校园大范围等不精确地点创建半透明范围；
- 保留原始来源平台、消息 ID、信息源时间和行动建议。

## 11. 使用任务图和行程

### 11.1 任务图

- 拖动空白处平移，滚轮或右上角按钮缩放。
- 点击主题中心查看该类任务；拖动主题中心可移动整组位置。
- 拖动外圈任务可改变顺序，拖到其他主题可重新归类。
- 右键任务可直接编辑或删除。
- 点击任务后，右侧浮窗显示时间、地点、来源、人物和建议。
- “标记完成”会同步到行程；再次点击可恢复完成前状态。
- 删除经过确认后彻底删除任务，但不会删除原始聊天。

任务默认归入校园、恋爱、朋友、学习、身心、生活之一。AI 分类不是不可更改，你可以拖动调整。

### 11.2 行程

行程明确区分：

- 目标时间：事情实际开始、发生或截止的时间；
- 信息源时间：你从哪条消息得知这件事的时间。

没有明确目标时间时，不会估算“10 分钟”“大概明天”等内容，而是显示信息源时间。长期事项可编辑为“长期事件”，开始和截止可精确到年份。

### 11.3 来源

任务详情和行程都可以打开“查看来源”。来源窗口应显示平台、提供者、消息时间和原始内容。若来源为空，说明它是手动任务或旧数据迁移时失去引用，重要任务应手动补充说明。

## 12. 地图与人物

### 12.1 地图

地图底图通过本地代理从多个公共 OpenStreetMap 兼容瓦片源读取；地点搜索使用 Nominatim，失败时回退 Photon。无需 API Key，但公共服务有使用政策和限流。

操作：

1. 搜索至少两个字的地址、校园或地点。
2. 在结果中选择，确认名称、分类、备注和精确度。
3. 或点击“添加标记”，再点击地图选点。
4. 已有点可拖到新位置；拖动后保存。
5. 详情中可编辑名称、分类、坐标、备注、精确/近似和范围半径。
6. 删除前确认；至少保留一个地点。

搜索不到时先尝试“城市 + 区 + 地点全名”，再用地图选点。公共地图不保证收录校内楼栋、商铺别名或新建地点。

### 12.2 人物

人物页按关系信号从深到浅排列，可搜索名称或来源平台。卡片会显示：

- 导出记录中可用的微信/QQ头像；
- 最早和最近可核实互动时间；
- 模型引用的消息数与来源平台；
- 有证据的偏好信号、保守人物刻画和互动建议；
- 关联任务；
- 原始私聊浮窗。

人物不是心理诊断。资料不足时应显示“需要更多信息源”，不能用流行人格标签填空。点击查看聊天会在本页打开虚拟滚动浮窗，不会把 2 万条消息一次渲染到 DOM。

人物支持全选、多选和批量删除。删除人物卡不会删除聊天，但该会话会记录为已忽略，避免同步后立刻恢复。

## 13. 保存、备份、迁移和清理

### 13.1 自动保存

任务、人物、地点、候选和布局写入 `data/state.json`；原始聊天单独写入 `data/chat-archive.json`；设置写入 `data/settings.ini`。浏览器内部还使用 localStorage 和 IndexedDB 作为界面缓存及目录授权存储，但发布目录中的文件是桌面/浏览器共享的主要持久化来源。

### 13.2 完整备份

1. 关闭桌面窗口和浏览器版命令行。
2. 复制以下目录到加密备份介质：

```text
data/
assets/img/
logs/
```

只想备份结果而不备份模型日志，可省略 `logs/`。只想迁移任务而不带聊天，可复制 `data/state.json`，但来源查看和人物证据会不完整。

### 13.3 恢复

1. 在同一或兼容版本中先启动一次，再完全退出。
2. 备份新安装产生的空 `data/`。
3. 用旧备份覆盖 `data/` 和需要的图片目录。
4. 启动并检查任务数、人物数、聊天数和设置。

当前版本没有正式 schema 迁移承诺。跨大版本恢复前务必保留原备份。

### 13.4 批量删除

- 人物页：全选或多选后删除人物卡。
- 选项“数据与存储”：批量清除任务或人物。
- 候选和磨合记录：分别在情报库/选项中删除。

界面中的“清除任务/人物”不等于清除原始聊天。若要彻底删除本机数据，退出 THEIA 后再删除对应运行时文件；操作前查看 [隐私与数据](PRIVACY_AND_DATA.md) 的路径表并做好备份。

## 14. 常见问题速查

### 双击后说缺少依赖

进入发布包 `app` 目录执行 `npm install`。确认 Node.js 版本至少 22.12。

### 出现 `Lock file can not be created` 或 Electron 单实例错误

先关闭旧窗口，再用发布启动器启动。不要复制运行中的 `data/electron/` 到另一个正在使用的目录。

### 模型列表 403

地址多半是网站首页或 Key 没有 `/v1/models` 权限。使用服务商明确提供的 API 地址；若模型列表接口被禁但已知模型 ID，可手动填写模型后保存。

### 大量 502

502 通常来自中转或上游，不是地图错误。用严格时间缩小范围、选择单一会话，并检查 `logs/tasks/` 中每段记录数和字符量。THEIA 会自动分段、快速重试并冷却故障通道；若服务商允许，可增加另一条独立 API 通道承接后续会话。多条 Key 若共享同一拥堵上游则没有帮助，THEIA 也无法修复服务商本身的容量不足。

### 已完成但 0 候选

0 候选有两种可能：确实没有仍需你行动的事项，或模型/字段有问题。先看进度摘要中的原始候选数，再查看任务日志中的模型原始响应；同时检查发言方向、时间戳和自定义提示词。

### 人物不更新

先确认所选内容包含发言方向可靠的私聊。新版会随任务请求联合处理人物；若某个模型不支持联合返回，右侧工作浮窗才会继续显示独立人物回退进度。停止处理会保留已生成卡片，但未完成私聊需要下次再跑。

### 头像不显示

检查 JSON 是否在消息、发言人对象或 `session.avatar` 中提供 HTTP(S) URL；旧 URL 过期、需要登录 Cookie、主机不在允许范围或网络 TLS 失败时，只能显示文字头像。

### 地图空白或搜索为空

确认网络可以访问公共 OSM 服务；等待限流恢复；尝试更完整的中文地址；仍失败时直接选点。企业/校园网络可能拦截地图瓦片或证书握手。

更完整的错误代码、日志阅读和恢复方法见 [故障排查手册](TROUBLESHOOTING.md)。

## 15. 使用原则

- 对任务：模型负责整理，你负责确认事实和决定是否行动。
- 对人物：保留原话证据，弱信号写成弱信号，不把一次表达升级成稳定特质。
- 对隐私：只向可信模型服务提交必要范围，日志和 Key 按私密数据保护。
- 对数据：升级、批量删除和迁移前先关闭程序并备份。
- 对自动化：THEIA 只处理授权导出，不提供绕过登录、数据库解密、密码提取或未授权采集。
