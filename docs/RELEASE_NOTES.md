# Release Notes

## 0.4.1 人际信息与重叠去重优化

发布日期：2026-08-05

发布类型：`0.4.0` 的向后兼容补丁版本。本版本不改变本地 HTTP 协议和归档 schema，重点修复分段重叠造成的重复候选，并让人物信息更适合长期、可验证的人际研究。

### 主要变化

- 任务候选在分段结果合并、候选审核队列写入和共享状态清理时统一去重；只有标题、描述、目标时间和地点都指向同一事件时才合并，不吞掉不同时间或地点的真实任务。
- 人物证据的身份键统一，要求证据引用当前分段核心消息，避免重叠上下文重复计数或把相邻会话的相似文本混为一谈。
- 人物页默认按最近互动排序，支持最近互动、资料完整度和姓名排序；搜索覆盖姓名、平台、事实、偏好、人物刻画和证据底稿，并提供消息量、会话数、双方发言分布和关联任务概览。
- 人物刻画与建议提示词优先关注明确边界、重复偏好、沟通方式和互动模式，建议尊重拒绝、确认意愿、倾听和提供低压力备选方案，并过滤操控、施压、制造嫉妒或无证据的情感判断。
- 对话浏览使用中文年月标签，支持按会话名称搜索，并优先用对方最近一条消息作为预览；人物证据超过紧凑显示数量时可以展开查看全部。

### 兼容性与验证

- 继续兼容 `0.4.0` 的任务、人物、情报、地图、设置和归档数据；无需迁移。
- 本次只更新源码版本并推送 `main`，不创建 GitHub Release 或版本标签。
- 已验证 `npm test`、`npm run test:e2e`、`npm run test:provider-pool`、`npm run test:utilities`、`npm run test:client`、`npm run lint`、`npm run build` 和 `git diff --check`。

## 0.4.0 大归档与同步架构升级

发布日期：2026-08-04

发布类型：在 `0.3.0` 稳定提炼基线上的兼容性增强版本，重点解决百万级聊天归档的重复上传、共享状态竞态和前端大组件维护成本。

### 主要变化

- 原始聊天归档采用 `theia-intel-archive/v1` append-only gzip JSONL segment。首个写入是 snapshot，后续写入是带 `upsert/delete` 操作的 delta；达到段数阈值后自动 compaction。旧 gzip/JSON 文件不会被直接删除，迁移失败可回滚。
- 新增 `POST /api/sync/intel/delta`。客户端在确认本地与共享归档版本一致后只发送 `upserts` 和 `deleteIds`；无法证明基线、首次导入或变更过大时自动回退 `POST /api/sync/intel` 全量协议。
- 浏览器缓存 schema 升级为 IndexedDB v2：`intelRecords` 按消息存储，`intelMeta` 存水位和 fingerprint，保留旧 `snapshots` store 用于一次性迁移。
- 新增 `useSharedSync`、`useIntelAnalysisSelection` 和候选队列组件；共享状态按字段比较，修复字段顺序不同导致的多端无意义回写。
- 新增 `useAiWorkflow`，把任务/人物串联、暂停检查点、恢复、失败重试和自动更新从视图移出；情报库进一步拆成 ArchivePanel、AnalysisPanel、CandidateQueue 和 ConversationBrowser。
- Electron 主进程优先使用系统凭据存储，INI 只保存 `credentialRef`；纯 Node 开发环境保留明文兼容路径。
- 新增运行标记、崩溃恢复状态、任务日志大小/数量轮转，以及 importer、分段、候选校验、存储、迁移、恢复和增量归档测试。
- 大于 1 MB 的 JSON/CSV/TXT 由 Web Worker 解析；附件队列在发送前显示大小、文本 token 粗估和模型侧图片/文档计费边界。
- 人物自动更新使用会话内容指纹：已有水位后只提交新增消息及每条新增消息之前最多 16 条上下文，成功后再推进该会话的人物水位；未变化私聊不会重复计费。
- 选项页可配置 OSM DE、OSM Standard、HOT 底图，自动/Nominatim/Photon 搜索源及 32–1024 MB 本地瓦片缓存；服务端按容量淘汰旧瓦片并保留公共服务政策链接和地图署名。
- 数据与存储面板显示共享 schema、归档 engine/记录/分段、迁移结果、回滚备份和非正常退出状态。
- 新增 Playwright 任务图视觉/拖拽回归和 Electron `safeStorage` 迁移烟测；发布工程新增 NSIS 安装器、GitHub 更新检查和可选 Windows 签名。

### 升级与回滚

- `0.3.0` 的任务、人物、地点、通道和旧聊天归档可以直接读取。首次启动会在 runtime 的 `migrations/` 写入备份，再建立新 schema。
- 归档迁移失败时不要删除旧文件；可使用 `npm run data:rollback -- --latest` 恢复最近的共享状态备份。回滚只处理状态/归档文件，不会修改 API 通道配置。
- 共享状态写入包含 `expectedUpdatedAt` 乐观版本号。发生 409 时客户端读取远端并按 ID 合并，再重试最多三次。

### 验证

- `npm test`：客户端、导入、分段、候选校验、存储、append-only archive、schema migration、恢复日志和 provider pool 全部通过。
- `npm run test:e2e`：任务图视觉基线、缩放、主题拖拽、无文本误选、地图配置和存储健康状态通过。
- `npm run test:desktop-smoke`：隔离 runtime 下 Electron 启动与 API Key 明文迁移通过。
- `npm run dist:unpacked` + `npm run test:unpacked-smoke`：ASAR 打包和打包后 `THEIA.exe` 实际启动通过。
- `npm run lint`、`npm run build`、`node --check server/index.mjs`、`node --check electron/main.mjs`、`git diff --check` 通过。

## 0.3.0 稳定并发与协议文档

发布日期：2026-08-04

发布类型：在 `0.2.1` 基础上的向后兼容稳定版本，包含并发上限调整、502 稳定性修复、可观测性补强和发布文档整理。

### 本版本解决的问题

- 修复任务请求在本地提示词/引用压缩阶段失败、实际上没有发出上游请求，却被 UI 统计为所有通道失败的问题。现在主任务提炼会在发送前完成可迭代引用范围压缩，并通过回归测试确认请求确实抵达假服务。
- 任务和人物默认使用分离的稳定路径：任务用 48 条/4,000 字符核心段，人物用 320 条/24,000 字符宽窗口；协议仍保留私聊联合任务+人物 schema，只有端点或结构化输出明确不支持时才回退 API 模式，不会复制一个大型请求。
- 人物证据提炼和人物归并取消旧的固定低并发，统一使用用户设置的全局分析并发；单通道仍由服务端 1–8 上限保护。
- 502、429、503、504、524、网络和超时错误的本地退避上限固定为 2 秒。上游返回很大的 `Retry-After` 不会让整个本地队列长时间冻结；失败工作保留在 session 中，断线后可通过 ack-v1 重复读取结果。
- 增强通道运行状态、共享 origin 容量、排队等待、尝试次数、API 模式回退和人物阶段日志，便于区分“没有发请求”“上游返回错误”和“模型返回空候选”。

### 吞吐模型

本版本的最大并发不是简单的“通道数量”：

```text
可用容量 = min(全局分析并发, 启用通道容量总和, 共享 origin 的有效容量)
```

全局分析并发范围为 1–64；单通道 `maxConcurrency` 范围为 1–8。例如 5 条独立配置、每条 8 个槽，理论容量是 40；如果 5 条配置最终指向同一个中转 origin，则仍受该 origin 的带宽、账户配额和服务端实际容量限制。同一会话的时间线分段继续串行，多个会话才会并行占用通道。

### 文档与发布

- 新增 [API 协议参考](API_PROTOCOL.md)，逐字段描述 `/api/ai/analyze`、人物证据、人物归并、任务建议、session enqueue/results/ack、通道状态、同步快照、日志和上游协议。
- 开发者文档更新为 `0.3.0`，补充实际并发、退避、发布布局、测试范围和数据边界。
- 发布包统一复制 `docs/`、三张界面截图和虚构示例；不会复制 `.theia-*`、API 配置、聊天、任务、人物、头像、背景、日志或 Electron profile。

### 兼容性与升级

- `package.json` 和 `package-lock.json` 版本提升为 `0.3.0`。
- 现有通道池、任务、人物、地点和压缩聊天归档保持读取兼容；升级前仍建议关闭程序并备份整个运行时目录。
- API Key 仍按当前产品设计以明文保存在 INI 中。不要将运行时 `data/`、`logs/` 或 `assets/img/` 上传到公共仓库。

### 发布前验证

- `npm test`：客户端持久化 29/29；provider pool 11/11。
- `npm run lint`：通过。
- `npm run build`：通过。
- `node --check server/index.mjs`：通过。
- `node --check electron/main.mjs`：通过。
- `git diff --check`：通过。

## 0.2.1 可恢复提炼

发布日期：2026-08-01

这是基于 0.2.0 的稳定性更新，重点解决长时间批量提炼不能安全中断的问题。

- 情报库的任务和人物提炼均支持“暂停并保存进度”。
- 已完成的会话 ID、所选范围、时间模式与当前阶段会写入本地数据和通用设置 INI；重新打开客户端后会询问是否继续。
- 恢复时只提交未完成会话；原始档案缺失、范围为空或没有可提炼私聊时，会自动清理检查点，避免反复弹窗。
- 确认生成任务后，临时“已生成候选”记录会立即移除；任务本身仍保留来源 ID，原始聊天档案也不会删除。
- 已连接的导出目录改为权威快照：文件集合发生变化时会完整重建归档并移除已不存在文件的旧消息；界面分别显示文件、消息和会话数量。

### 从 0.1.0 升级概览

0.1.0 已具备导入聊天、任务图、行程、人物、地图和本地模型配置的基础能力。至 0.2.1，提炼流程已升级为会话级全量覆盖分段、多 API 通道并发、可审计日志、候选磨合与可恢复批处理，并补齐桌面/浏览器同步、头像缓存、地图标记编辑和外观自定义。现有本地任务、人物、地点和原始档案保持兼容；升级前仍建议备份运行时目录。

## 0.2.0 多通道提炼引擎

发布日期：2026-07-31

发布类型：向后兼容的源码功能版本

### 版本目标

0.2.0 重点解决几十万条消息、数千个会话下的吞吐、重复 token 消耗和故障定位问题。提炼仍以“一个会话的时间线”为语义边界：不同会话可以并行，同一会话的连续分段保持串行和少量上下文重叠，避免为了并发打乱对话顺序。

### 模型通道池

- 选项页可以添加、编辑、启停、设为主通道或删除多条 OpenAI 风格 API 通道。
- 每条通道独立保存服务地址、明文 API Key、模型、API 模式、模型列表和 1–8 的并发容量。
- （0.2.0 历史行为）全局“并发会话”支持 1–32；实际吞吐受全局并发、健康通道总容量和服务商额度共同限制。0.3.0 已提升到 1–64。
- 调度器优先选择当前负载比例最低且未冷却的通道，负载相同时使用稳定的轮转规则。
- （0.2.0 历史行为）429、502、503、504、524、超时和网络错误只让对应通道进入 1–12 秒指数冷却，不阻塞其他健康通道。0.3.0 已固定为最多 2 秒本地退避。
- 同一个失败请求不会广播给所有服务商。客户端重试时重新申请通道，避免重复计费和重复候选。
- 旧的单通道 `/api/ai/config` 接口继续兼容；新增通道池 CRUD 接口和运行状态信息。

### 提炼速度与 token

- 私聊任务和人物证据通过一次 `/api/ai/analyze` 联合返回，正常情况下不再把同一私聊重新上传给 `/api/ai/people`。
- 群聊保持任务-only，避免无依据地为群成员生成人物卡。
- 只有旧兼容服务没有返回人物工作流结果，或联合处理未覆盖某个私聊时，才使用独立人物接口回退。
- 提示词的稳定证据规则前置，日期、分段元数据、磨合反馈和聊天正文后置，便于支持 prompt cache 的模型复用固定前缀。
- 任务-only、任务+人物联合、人物归并和任务建议使用不同的输出预算，避免所有请求预留同样大的输出。

### 可靠性与诊断

- Responses API 仅在端点或结构化输出被明确判定为不支持时回退到 Chat Completions。普通 502、503、504、超时和网络故障不再复制大请求尝试另一种 API 模式。
- 调试日志记录通道 ID、通道名、排队时间、尝试次数、回退、冷却、token 用量和失败阶段；API Key 不写入日志。
- 每个任务工作单元继续保存独立时间戳日志，便于从单个会话和分段定位问题。
- 修复 `compactRecordRefRanges()` 只能处理数组的问题。调用方传入 `Set` 时曾在提示词构造阶段抛出 `values.map is not a function`，造成所有通道看似同时失败、`providerAttemptCount` 为 0，实际没有产生任何上游请求或 token 消耗。
- 范围压缩函数现在接受任意 iterable，主任务提炼路径增加回归测试，确保分段提示词能够构造并真正到达模型通道。

### 配置与兼容性

- `settings.ini` 升级到 v3，增加 `[providers]` 通道数组和主通道 ID；旧 `[provider]` 单通道配置保留为兼容入口并可自动读取。
- 客户端并发设置增加 `analysisConcurrency`，旧配置缺失时使用保守默认值。
- 原有任务、人物、地点、候选、聊天归档、背景和头像目录不需要迁移。
- API Key 仍按产品当前设计明文保存在本机 INI。升级不会上传配置，但用户仍应把 `settings.ini` 当作密码文件保护。

### 使用建议

1. 首次升级后在“选项 > 模型通道池”确认原通道显示可用。
2. 先保留单通道容量 1–2、全局并发 2–4，用一个短私聊验证候选和人物结果。
3. 只有服务商明确允许更高并发时再逐步增加；多条 Key 如果共享同一账户或同一上游，通常不会线性提速。
4. 处理大量记录时优先使用严格时间范围。历史段仍可用于人物事实，但普通过期事项不会重新生成为任务。
5. 出现批量失败时先看 `providerAttemptCount`：为 0 通常表示本地校验或提示词构造失败，大于 0 才表示请求已经到达供应商链路。

### 验证

本版本发布前完成：

- `npm test`：通过。两个 loopback 假服务验证双通道并行分流、单通道 502 冷却、备用通道接管、主提炼请求真实进入供应商调用，以及日志不包含测试 Key。
- `npm run lint`：通过。
- `npm run build`：通过，生成生产前端；保留一个已有的单 chunk 大于 500 kB 警告。
- `git diff --check`：通过。

### 已知限制

- 同一会话的片段为保证时间线语义仍串行，单个超长会话不会占满全部通道。
- 通道池不能突破服务商账户级、IP 级或共同上游的带宽限制，也不应用于规避访问控制或安全策略。
- 自动化测试当前覆盖服务端通道池与主提炼关键路径，尚未覆盖完整导入器、React 交互和 Electron 端到端流程。
- 当前没有设置数据库加密、后台系统服务或自动更新器；升级前仍建议备份运行时目录。
