# HYPERION 隐私与数据说明

HYPERION 处理聊天、关系、位置、行程和模型密钥，默认应视为高敏感个人数据。本说明列出数据在哪里、何时离开本机、如何备份，以及发布或求助时必须删除什么。

## 1. 发布包的脱敏保证

干净发布包不应包含：

- 真实聊天、朋友圈、校园记录或附件；
- 真实任务、人物、地点、候选和磨合记录；
- 用户名称、头像、联系人头像或自定义背景；
- 模型服务地址、模型列表和 API Key；
- Electron/浏览器 profile、Cookie、缓存和目录授权；
- 摘要日志或完整模型工作日志；
- 源工作区绝对路径、临时文件和 Git 元数据。

`data/examples/` 只能包含虚构名字、虚构内容和不可解析到真实服务的 URL。默认背景/头像必须为项目生成的中性素材，不得复制用户真实头像或含个人偏好的历史背景。

## 2. 运行后产生的数据

发布布局：

| 路径 | 内容 | 敏感级别 | 删除影响 |
| --- | --- | --- | --- |
| `data/state.json` | 任务、人物、地点、候选、布局、忽略列表 | 高 | 丢失主要成果和布局 |
| `data/chat-archive.json.gz` | gzip 压缩的完整导入聊天归档 | 极高 | 无法查看来源或再次从本地归档提炼 |
| `data/settings.ini` | 名称、外观、提示词、模型 URL、明文 API Key | 极高 | 设置重置，模型需重新配置 |
| `data/electron/` | Chromium profile、缓存和会话数据 | 高 | 桌面 profile 重置 |
| `data/runtime/desktop.pid` | 当前桌面进程 ID | 低 | 运行中删除会影响启动器识别 |
| `assets/img/avatars/` | 下载的联系人头像及 URL hash 元数据 | 高 | 头像需重新下载或显示占位符 |
| `assets/img/backgrounds/` | 用户上传背景和用户头像资产 | 中到高 | 外观图片失效 |
| `logs/ai-debug.jsonl` | 不含正文的管线摘要 | 中 | 降低调试能力 |
| `logs/tasks/*.jsonl.gz` | 压缩的模型输入、输出、错误，可能含聊天正文 | 极高 | 无法复盘具体模型行为 |

开发布局使用根目录 `.hyperion-*` 对应项，敏感等级相同。

## 3. 哪些数据会离开本机

### 3.1 模型服务

只有用户启动任务/人物提炼、人物归并或任务建议时，相关数据才发送到配置的模型服务。

- 任务与人物分析：所选会话范围内的消息时间、类型、正文、发言人、方向和短引用；可选附件。
- 人物归并：已核验的人物事实/偏好/画像，不发送原始全文。
- 任务建议：任务、关联人物摘要、地点和可选天气上下文。
- 鉴权：API Key 通过 Authorization header 发给用户配置的服务。

第三方中转可能记录请求、转发给其他上游、跨境处理或用于风控。HYPERION 无法替你验证其隐私承诺。敏感聊天应使用你信任且条款清楚的服务，并遵循最小范围原则。

### 3.2 地图和地理搜索

- 地图瓦片：服务端向 OSM 公共镜像发送标准 z/x/y 坐标。
- 地点搜索：只发送用户主动输入的搜索关键词，不发送任务标题、人物或备注。
- 搜索可能依次访问 Nominatim、Photon、ArcGIS、Wikidata 和 Open-Meteo。

搜索词本身可能暴露学校、住址或常去地点。精确家庭地址可直接手动选点，避免把完整地址发给公共地理搜索。

### 3.3 天气

未来 16 天内有目标时间和地点的任务，可向 Open-Meteo 发送经纬度和日期。不会发送任务名称或人物。

### 3.4 头像

远程 QQ/微信头像经本地代理从导出 URL 下载。请求会到相应图床，可能暴露网络地址和资源访问时间。成功后本地缓存。

### 3.5 在线语录

侧栏语录请求 Hitokoto，不发送聊天、任务或用户名称。失败时使用离线句库。

## 4. API Key 保护

当前产品为方便编辑和桌面/浏览器共用，按用户要求在 `settings.ini` 中明文保存 API Key。风险包括：

- 任何能读取该文件的本机进程都可能看到 Key；
- 误把发布运行目录同步到云盘或 Git 会泄露；
- 截图选项页会直接包含 Key；
- 完整系统备份可能包含 Key。

建议：

1. 使用权限最小、可撤销、有限额度的 Key。
2. 不与主账户高权限 Key 共用。
3. 不把运行目录放进公开同步目录。
4. 分享屏幕前关闭选项页。
5. 怀疑泄露时立即在服务商后台吊销，而不是只删除本地文件。

正式产品化应迁移到 Windows Credential Manager/DPAPI 或其他系统凭据存储，同时保留可控导出机制。

## 5. 本地服务安全边界

本地 API 默认只监听 `127.0.0.1:8787`，CORS 只接受 localhost/127.0.0.1 origin。Electron renderer 启用 context isolation、禁用 Node integration 并开启 sandbox。

限制：

- API 没有用户身份认证，因为设计目标仅是本机 loopback。
- `/api/settings` 为了编辑可返回明文 Key。
- 若用户主动用反向代理、端口转发或防火墙规则暴露 8787，任何边界保证都会失效。
- 本机恶意软件仍可读取运行目录或访问 loopback。

不要把 8787 暴露到局域网或公网。

## 6. 媒体代理与 SSRF 防护

头像代理仅允许 HTTP(S) 且主机在 QQ/微信图床白名单，重定向每一步重新校验，最多 3 次；响应必须为受支持图片 MIME，并受大小和超时限制。

地图瓦片只允许两个固定 OSM 镜像主机。背景外链由 Chromium 直接显示，设置层只允许 HTTP(S)；不允许 `file:`、任意本地路径或脚本协议。

任何扩大头像或地图白名单的改动都应审查：DNS rebinding、私网 IP、重定向、响应大小、MIME 欺骗和缓存路径穿越。

## 7. 日志脱敏边界

摘要日志刻意不记录正文、附件 data URL、请求头和 Key。工作日志为了调试模型会记录请求正文；序列化器只自动清理名称为 key/apiKey/authorization/token 的字段，并把 data URL 替换为大小。

这不意味着工作日志“已匿名化”。昵称、聊天内容、位置、会话名称、普通 HTTP URL 和模型输出仍可能识别个人。

分享日志前：

1. 复制到临时位置，不直接编辑唯一原件。
2. 删除或替换正文、昵称、群名、学校、住址、电话、账号 ID 和 URL。
3. 删除模型服务域名及可关联请求 ID。
4. 再次全文搜索 `sk-`、`Bearer`、手机号、邮箱和真实姓名。
5. 只分享能复现问题的最小几行。

## 8. 备份策略

### 8.1 完整备份

退出所有 HYPERION 实例后，备份：

```text
data/
assets/img/
logs/        # 若需要保留模型审计
```

建议使用 BitLocker、加密移动盘或加密归档。普通 ZIP 没有足够保护，除非使用现代加密并设置强密码。

### 8.2 备份频率

- 高频使用：每天增量、每周完整；
- 大规模导入或版本升级前：立即完整备份；
- 批量删除人物/任务前：至少备份 `state.json`；
- 更换模型提示词并大批提炼前：备份 state、settings 和 logs。

### 8.3 校验

重要备份应记录文件大小和 SHA-256。恢复测试比“备份命令没报错”更重要：在隔离目录启动同版本，确认任务、人物、归档和设置可读。

## 9. 数据删除

界面删除对象与物理删除文件不同：

- 删除任务：从 state 移除任务，原始聊天仍在。
- 删除人物：移除人物卡，并记录忽略会话，原始聊天仍在。
- 删除候选/反馈：移除对应状态，不删除引用消息。
- 清空聊天归档：当前应在确认备份后，通过受控数据管理或退出后删除 archive；不要把清任务按钮误当成清聊天。

若要从电脑彻底移除发布实例：

1. 退出 HYPERION。
2. 吊销模型 Key（如果目录可能被他人接触）。
3. 删除发布目录及其备份副本。
4. 清理回收站和云盘版本历史。
5. 了解 SSD/文件系统可能保留底层恢复痕迹；高安全需求使用全盘加密和合规擦除策略。

## 10. 发布与问题报告检查表

- [ ] 发布器目标是新目录，不覆盖个人运行目录。
- [ ] 目标中没有 `state.json`、`chat-archive.json.gz`、`settings.ini`。
- [ ] `logs/` 只有 README 和空占位。
- [ ] `assets/img/avatars/` 为空占位。
- [ ] 背景和默认头像是通用项目素材。
- [ ] 示例聊天全部虚构，URL 使用 `.invalid`。
- [ ] 全文搜索真实昵称、Key 前缀、服务域名和用户路径。
- [ ] ZIP 生成后再次检查内容清单并计算 SHA-256。
- [ ] 问题报告只附最小脱敏日志。

## 11. 未成年人和他人数据

聊天记录不仅属于导出者，也包含对方的信息。使用模型服务前应考虑对方合理隐私预期、服务条款、学校规定和当地法律。不要把同学、未成年人、健康、财务或亲密关系信息提交给不可信中转，也不要用人物画像进行骚扰、操控或歧视。

人物建议应尊重边界，事实不足时明确“不足”，不把模型猜测包装成心理结论。
